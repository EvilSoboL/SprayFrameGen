# SprayFrameGen

Каркас приложения по [issue #2](https://github.com/EvilSoboL/SprayFrameGen/issues/2):
полная конфигурация, строгая валидация, JSON, метаданные окружения и независимые
случайные потоки. По issue #3 реализована генерация параметров капель первого кадра.
По issue #4 реализованы движение, замена вышедших капель и признаки границ/перекрытий.
Рендер и экспорт изображений относятся к issues #5–#7.

## Подготовка и запуск

Целевая платформа — Windows x64. Стек: CPython 3.14, Tkinter из поставки Python,
NumPy 2.3.5, Pillow 12.0.0. Проверяемая базовая среда — CPython 3.14.0 x64.
Выбор Pillow основан на поддержке одноканального режима I;16; тесты проверяют
сохранность значений PNG 8/16 бит и TIFF 16 бит.

В корне проекта, при установленном Python 3.14 с Tcl/Tk:

```powershell
py -3.14 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.\run.bat
```

Установка зависимостей выполняется один раз. После подготовки приложение работает
офлайн. Для подготовки без интернета можно заранее скачать Windows x64 wheels
для Python 3.14 и установить через `pip install --no-index --find-links wheels -r requirements.txt`.
Окончательная поставка без Python и установщик относятся к issue #10.

Окно позволяет создать настройки идеального/реалистичного режима, редактировать
JSON, проверить его, открыть и сохранить файл. Кнопки «Новая» создают новый seed
и заменяют содержимое редактора. Полный интерфейс с отдельными полями и предпросмотром
относится к issue #8. Папка экспорта не нужна для проверки настроек.

```powershell
.\run.bat --check docs\examples\config.default.json
.\run.bat --new settings.json
.\run.bat --smoke-test
.\run.bat --environment
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe -m unittest discover -s tests -p ui_smoke.py -v
```

Последняя команда отдельно проверяет запуск окна, кнопки проверки/сохранения/загрузки
и вывод ошибки; ей нужен интерактивный Windows-сеанс с доступным Tcl/Tk.

При недоступном Tcl/Tk запуск сообщает по-русски о проблеме и предлагает проверку
JSON без окна. `run.bat` использует UTF-8 и окончания строк CRLF (закреплены в
`.gitattributes`); отсутствие `.venv` также сопровождается русским сообщением.

Проверка issue #2 от 15.09.2026 на Windows 10 x64 / CPython 3.14.0:
28 основных тестов и отдельный тест окна прошли, команды `run.bat --check` и
`run.bat --smoke-test` выполнены успешно, `pip check` не обнаружил конфликтов.
Тест окна выполнялся вне песочницы, ограничивающей загрузку Tcl. Проверки серии
изображений, полного интерфейса и окончательной поставки относятся к следующим issues.

## Архитектура

| Модуль | Ответственность |
|---|---|
| `configuration.py` | Неизменяемые dataclass-модели, defaults, общий валидатор, JSON |
| `environment.py` | Фактические версии runtime, библиотек, кодеков и хеш сборки |
| `model` | Неизменяемое состояние капли, форма и распределения (#3) |
| `geometry` | Непрерывные проекции, активность, границы и пространственный поиск перекрытий (#4) |
| `render` | Будущий рендер в float64 (#5–#6) |
| `export` | Будущие PNG/TIFF и CSV (#5) |
| `generation` | Подготовка запуска, независимые RNG, модель серии и замена капель; жизненный цикл (#7) |
| `ui` | Начальное окно настроек; полный GUI (#8) |

Ручные изменения через `update_configuration(config, {"camera.exposure_us": 20})`
и импорт JSON используют `from_mapping`. Ошибка содержит путь поля и русскую причину.
При загрузке отсутствующие поля не подменяются defaults; неизвестные поля игнорируются
с предупреждением. При сохранении записывается фактическая версия программы.
Метаданные загруженной серии сохраняются до `generation.prepare`, который очищает
`run` и создаёт потоки с исходного seed. Проверка места и прав экспорта — issue #7.

## Повторяемость

Алгоритм — явный `numpy.random.PCG64`, обёрнутый `Generator`.
`SeedSequence(seed).spawn(2)` всегда создаёт ребёнка 0 для модели, ребёнка 1 для шума,
даже при выключенном шуме. Каждый предпросмотр и каждый экспорт заново вызывают
`prepare`; глобальный RNG не используется. Внутри каждого потока вызовы последовательны.
Порядок выборок свойств капли зафиксирован регрессионным тестом для seed=123;
менять его без изменения сборки нельзя. Параллельное расходование одного потока запрещено.

`build_id` — SHA-256 отсортированных имён и содержимого всех Python-файлов пакета
(LF-нормализация); версии runtime, NumPy, Pillow, zlib, libtiff и Tcl/Tk сохраняются
отдельно. Смена исходников автоматически меняет идентификатор. Профиль — `standard-v1`.
Точные патчи Tcl/Tk читаются из скриптов установленного CPython без создания окна.

Различие версии программы, сборки или окружения вызывает предупреждение при загрузке.
Неизвестный профиль или основная версия схемы — ошибка. Гарантируемый будущий сценарий
побайтового повтора — та же установленная сборка на том же компьютере. Тесты этого
этапа подтверждают повтор параметров капель и независимость потоков; повтор файлов
серии будет проверен после реализации рендера и экспорта.

## Генерация параметров капель (#3)

```python
from sprayframegen.configuration import new_configuration
from sprayframegen.generation import generate_initial

config = new_configuration(seed=123)
droplets = generate_initial(config)
first = droplets[0]
a, b = first.semi_axes_at(first.center_x_px, config.camera.width_px)
```

`generate_initial` возвращает неизменяемые состояния `Droplet` первого кадра с ID
от 1 до `count_per_frame`; каждый вызов начинает выборку заново от seed. Для
последовательного создания капель доступны `prepare` и `DropletSampler(config,
streams.model)`. `sample_initial` выбирает одну каплю, `initial_population` —
`count_per_frame` капель; обе операции продолжают RNG и счётчик ID этого sampler.

Порядок на каждую каплю: диаметр → группа → направление (для выброса абсолютный
угол, затем знак) → модуль скорости → X → Y → `q_left` → `angle_deg` → расфокусировка.
Координаты X и Y выбираются независимо с повторением за пределами кадра.
Фиксированные значения и отключённые свойства не расходуют RNG; в идеальном
режиме `q_left=1`, `angle_deg=0`. Явно включённая расфокусировка работает в обоих режимах.

Повторная выборка ограничена 100 000 попытками на одно значение; последняя
успешная попытка принимается. При исчерпании возникает `SamplingError` с параметром,
распределением и границами. Этот же защитный лимит используется для координат
и проверки открытого интервала угла выбросов. Кандидаты не обрезаются до границ.
`semi_axes_at` вычисляет форму по текущей X с сохранением эквивалентного диаметра;
перемещение, замена капель и признаки пересечений реализованы в #4 (см. ниже).

Проверка #3 от 15.09.2026: 39 основных тестов прошли, из них 11 новых тестов модели.
Проверены выборки по 10 000 капель для обоих распределений размеров и всех трёх
уровней концентрации, углы с учётом усечения, скорости, форма, расфокусировка,
ошибки и повторяемость. Графический предпросмотр и экспорт пока не подключены.

## Модель серии и геометрия (#4)

```python
from sprayframegen.configuration import new_configuration
from sprayframegen.generation import generate_frames

for frame in generate_frames(new_configuration(seed=123)):
    state = frame.droplets[0]
    print(frame.frame_number, frame.time_us, state.droplet.droplet_id,
          state.is_new, state.border, state.overlap)
```

Итератор выдаёт неизменяемые `Frame` по одному, без накопления всей серии. Состояние
`FrameDroplet` содержит `droplet`, актуальные `semi_major_px`, `semi_minor_px` и три
признака. Первый кадр соответствует `generate_initial`, время равно нулю. Дальше
координаты изменяются на `v × frame_interval_us / scale_um_per_px` без округления.
Постоянные параметры и ID сохраняются; полуоси пересчитываются по текущей X.

После полного выхода исходной проекции новая капля создаётся в том же кадре на
X=0. `sample_replacement` использует тот же RNG и счётчик ID; порядок выборок
совпадает с первоначальной каплей, кроме отсутствующей выборки X. Замены выполняются
по возрастанию прежних ID, состояния кадра сортируются по новым ID. Количество
остаётся постоянным, включая полностью совпавшие проекции. `is_new` выставляется
только в первом кадре присутствия ID. Каждый вызов итератора начинает отдельную серию
от seed, поэтому частичный просмотр не расходует состояние последующего запуска.

Геометрия работает в непрерывной области `[0,W] × [0,H]`, до оптических эффектов.
Сетка ограничивающих прямоугольников отбирает кандидатов, затем аналитические
вертикальные сечения повёрнутых эллипсов проверяют общую внутреннюю область кадра.
Разность нижней и верхней границ сечения — выпуклая функция; её минимум ищется
золотым сечением, максимум 80 итераций. Касание без площади и пересечение только
снаружи не дают `overlap`. Активность у углов проверяется по самой проекции.

Для подавления ошибок float64 при внешних касаниях используется допуск
`32 × ulp(max(W,H))` по вертикальному зазору (около `3,6×10⁻¹²` пикселя для
640×480). Перекрытия в пределах этого численного допуска трактуются как касания.
Это численная проверка непрерывной геометрии, без растровой маски и полигонального
приближения эллипса. Проверка `border` сравнивает крайние точки проекции с кадром;
касание изнутри не считается выходом за границу.

Проверка #4 от 15.09.2026: **60 основных тестов прошли**, включая 21 новый тест
геометрии и серии. Проверены массовая замена 10 000 капель, 1000 кадров, уникальность
ID, постоянство параметров, допуск координат 0,01 пикселя, три концентрации замен,
касания и углы, повёрнутые эллипсы, вложенность и пересечения только снаружи.
Результат пространственного поиска сравнивается с полным перебором пар;
1000 случайных пар кругов дополнительно проверены по аналитическому расстоянию.
Объединённая нагрузка 1000 кадров × 10 000 капель с рендером относится к D09.
