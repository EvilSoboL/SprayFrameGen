# Техническое задание на разработку программы генерации синтетических изображений распыла

**Рабочее наименование:** «Генератор синтетических изображений распыла»  
**Версия документа:** 1.1\
**Дата:** 14.09.2026  
**Целевая платформа:** Windows x64

Версия 1.1 включает согласованные ответы на вопросы 1–33 по issue №1. [Правила генерации](generation_rules.md) и [контракт конфигурации, рендера и экспорта](configuration_contract.md) являются нормативными дополнениями: они задают подробные формулы, граничные случаи, все поля и численные алгоритмы. Спецификация согласована; реализация и приёмочные проверки приложения выполняются в последующих issues.

## 1. Назначение программы

Программа предназначена для генерации последовательностей синтетических изображений капельного распыла, имитирующих кадры высокоскоростной видеосъёмки. Сформированные изображения и эталонные параметры капель должны использоваться для верификации отдельной программы анализа распыла: проверки определения размеров капель, их координат и скоростей перемещения.

Программа должна формировать:

- последовательность из 2–1000 кадров;
- изображения с заданным количеством капель, распределением их размеров и скоростей;
- постоянные траектории одних и тех же капель между соседними кадрами;
- синтетический статичный фон и настраиваемые оптические эффекты;
- эталонную таблицу параметров каждой капли на каждом кадре;
- файл полной конфигурации, позволяющий повторить генерацию.

На экспортируемых кадрах должны присутствовать только капли и синтетический фон. Сопло, шкала, подписи, временные метки, идентификаторы, векторы и другие служебные элементы на изображения не наносятся.

## 2. Термины и определения

- **Серия** — набор последовательно сгенерированных кадров, созданных с одной конфигурацией и одним значением `seed`.
- **Эталонные данные (ground truth)** — точные параметры искусственно созданных капель до их распознавания сторонней программой.
- **ID капли** — уникальный целочисленный идентификатор, сохраняющийся на всём протяжении нахождения капли в поле кадра.
- **Чистый кадр** — изображение без служебной разметки.
- **Статичный фон** — одна базовая матрица фона, неизменная в пределах серии. Покадровый сенсорный шум рассматривается отдельно и может изменяться.
- **Эквивалентный диаметр** — диаметр круга, площадь которого равна площади проекции капли.
- **Активная капля** — капля с положительной площадью исходной проекции внутри кадра в середине выдержки; учитывается даже при полном закрытии другой каплей.
- **Граничная капля** — активная капля с положительной площадью проекции и внутри, и снаружи кадра. Касание края изнутри не делает каплю граничной.

## 3. Условия эксплуатации и запуска

1. Программа используется локально на одном компьютере пользователя.
2. Поддерживаемая операционная система — Windows 10/11 x64.
3. Программа запускается с помощью файла `run.bat`.
4. Допускается поставка исходного кода и локального окружения выполнения вместо установщика.
5. После подготовки рабочего окружения программа должна полностью работать офлайн.
6. Во время работы запрещены обязательные сетевые запросы, телеметрия и загрузка внешних ресурсов.
7. Интерфейс программы — только на русском языке.

## 4. Общий сценарий работы

Пользователь должен иметь возможность:

1. Создать новую конфигурацию или открыть ранее сохранённый JSON-файл.
2. Выбрать параметры виртуальной камеры и серии кадров.
3. Задать количество, размеры, пространственное распределение и скорости капель.
4. Настроить фон, внешний вид капель, шум, расфокусировку и размытие от движения.
5. Получить предварительный просмотр кадра.
6. При необходимости включить поверх предпросмотра служебный слой с ID, контурами и векторами скорости.
7. Выбрать папку назначения и запустить генерацию.
8. Наблюдать прогресс и при необходимости отменить операцию.
9. Получить папку серии с изображениями, CSV-разметкой и JSON-конфигурацией.

## 5. Входные параметры

### 5.1. Параметры серии и камеры

| Параметр | Требование |
|---|---|
| Количество кадров | Целое число от 2 до 1000 |
| Количество капель | Точное число капель на каждом кадре, от 1 до 10 000 |
| Разрешение | Один из пресетов: 640×480, 1024×768, 1280×1024, 1920×1080 |
| Масштаб | Положительное число, мкм/пиксель |
| Межкадровый интервал | Положительное число, мкс |
| Выдержка | Положительное число, мкс; не более межкадрового интервала |
| Разрядность и формат | PNG 8 бит; PNG 16 бит; TIFF 16 бит |
| Seed | Автоматически создаваемое целое число от 0 до 4294967295 включительно с возможностью ручного ввода |

### 5.2. Параметры размеров капель

Пользователь выбирает один из двух законов распределения:

1. **Нормальное распределение:** средний диаметр `μd`, мкм, и стандартное отклонение `σd`, мкм.
2. **Логнормальное распределение:** медианный диаметр `d50`, мкм, и геометрическое стандартное отклонение `σg`.

Дополнительные ограничения:

- минимальный диаметр проекции равен 3 пикселям;
- максимальный диаметр задаётся пользователем в мкм;
- максимальный диаметр должен быть не меньше минимального;
- значения, выходящие за допустимый диапазон, должны генерироваться повторно, а не обрезаться до границы;
- нулевые и отрицательные диаметры недопустимы.

Пересчёт диаметра из физических единиц в пиксели:

```text
d_px = d_um / scale_um_per_px
```

Для нормального распределения используется усечённая выборка:

```text
d ~ N(μd, σd²),  d_min <= d <= d_max
```

Для логнормального распределения:

```text
ln(d) ~ N(ln(d50), ln(σg)²),  d_min <= d <= d_max
```

где `σg >= 1`.

### 5.3. Пространственное распределение капель

На первом кадре центры капель формируются по двумерному нормальному распределению относительно центра изображения. Значения за пределами изображения генерируются повторно.

Пользователь выбирает один из трёх готовых уровней концентрации:

| Уровень | σx | σy | Назначение |
|---|---:|---:|---|
| Низкая | `0,45 × W` | `0,45 × H` | Слабое сгущение к центру |
| Средняя | `0,30 × W` | `0,30 × H` | Выраженное сгущение |
| Высокая | `0,18 × W` | `0,18 × H` | Основная масса капель в центральной области |

Здесь `W` и `H` — ширина и высота кадра в пикселях. Центр распределения фиксирован в точке `(W/2, H/2)`.

Случайные перекрытия проекций капель разрешены. Наличие перекрытия не должно приводить к объединению записей в эталонной таблице.

### 5.4. Распределение скоростей

Основное направление движения — слева направо. Согласно согласованным решениям issue №1:

- каждая создаваемая капля с вероятностью 95% относится к основной группе и с вероятностью 5% — к выбросам; принадлежность сохраняется на всей траектории;
- направление основной группы отклоняется от горизонтали вправо не более чем на 30° вверх или вниз;
- отклонение выбросов строго больше 30° и строго меньше 90°; отклонения вверх и вниз равновероятны;
- строго вертикальное движение и движение справа налево не допускаются;
- после создания капли её `Vx` и `Vy` остаются постоянными на всей траектории.

Пользователь задаёт среднее, стандартное отклонение, минимум и максимум **модуля скорости**: `speed_mean_m_s`, `speed_std_m_s`, `speed_min_m_s`, `speed_max_m_s`. Модуль выбирается из нормального распределения с повторной выборкой вне границ, независимо от направления и одинаково для обеих групп. Требуется `0 < speed_min_m_s <= speed_max_m_s`, `speed_std_m_s >= 0`; неподвижные капли не генерируются. Правила нулевого разброса, равных границ и лимита повторных попыток приведены в дополнении.

Угол основной группы выбирается из нормального распределения вокруг `0°` с настраиваемым `direction_std_deg` (по умолчанию `10°`) и повторной выборкой вне `[-30°, 30°]`. При нулевом разбросе основная группа движется строго вправо. Абсолютный угол выброса равномерно выбирается строго между `30°` и `90°`, знак выбирается с равными вероятностями.

Компоненты вычисляются автоматически: `Vx = v × cos(theta)`, `Vy = v × sin(theta)`, где `v` — модуль скорости, `theta` — угол в радианах; положительный угол направлен вниз. В CSV сохраняются компоненты и модуль. Независимые настройки `Vx` и `Vy` заменены настройками модуля и углового разброса. Полные правила, поля и примеры приведены в [правилах генерации, раздел 8](generation_rules.md#8-основное-направление-движения-и-редкие-выбросы).

### 5.5. Перемещение капель

Используется экранная система координат:

- начало координат расположено в левом верхнем углу;
- ось `X` направлена вправо;
- ось `Y` направлена вниз;
- знак `Vx` и `Vy` соответствует этим направлениям.

Непрерывная область кадра — `[0, W] × [0, H]`. Центр пикселя в столбце `j` и строке `i` при нумерации с нуля находится в `(j+0,5; i+0,5)`. Например, для `640×480` центры крайних пикселей равны `(0,5; 0,5)` и `(639,5; 479,5)`. Координаты центров капель непрерывны, без округления к пикселям.

Для капли, существующей на двух соседних кадрах, перемещение рассчитывается по формулам:

```text
dx_px = Vx_m_s × frame_interval_us / scale_um_per_px
dy_px = Vy_m_s × frame_interval_us / scale_um_per_px

x(i + 1) = x(i) + dx_px
y(i + 1) = y(i) + dy_px
```

Равенство основано на соотношении `1 м/с = 1 мкм/мкс`.

Момент времени кадра:

```text
time_us = (frame_number - 1) × frame_interval_us
```

Ускорение, случайное блуждание, столкновение, слияние и дробление капель в текущую версию не входят.

### 5.6. Выход капель и создание новых

1. Пока площадь исходной проекции внутри кадра положительна, капля сохраняет свой ID и постоянные индивидуальные параметры, включая случаи полного закрытия другой каплей. Форма реалистичной капли меняется по закону округления из раздела 6.1.
2. Если площадь проекции внутри кадра стала нулевой, в том числе при касании края снаружи, капля удаляется из активного набора.
3. В том же кадре создаётся новая капля с новым, ранее не использовавшимся ID.
4. Новая капля получает новые размер, форму, скорость и степень расфокусировки по заданным распределениям.
5. Количество геометрически активных капель на каждом кадре должно точно соответствовать значению, введённому пользователем; оно не обязано совпадать с числом различимых объектов на изображении.

Все новые капли, заменяющие вышедшие, появляются на левой границе, включая выбросы. Первоначальное заполнение кадра сохраняет распределение из раздела 5.3.

Центр новой капли размещается непосредственно на левой границе (`center_x_px=0`), поэтому на первом кадре её появления капля видна частично и получает `border=true`. Координата Y выбирается по нормальному распределению вокруг `H/2` со стандартным отклонением `0,45 × H`, `0,30 × H` или `0,18 × H` для низкой, средней или высокой концентрации соответственно. Значения вне стороны кадра выбираются заново.

## 6. Формирование изображения

### 6.1. Режимы изображения капель

Должны быть доступны два переключаемых режима.

#### Идеальный режим

- капли имеют форму круга;
- круг имеет заданный эквивалентный диаметр;
- заливка однородная и непрозрачная: нормированная яркость `0,10` на светлом фоне и `0,90` на тёмном;
- оптический контур и случайная несферичность не используются;
- гауссова расфокусировка по умолчанию выключена; пользователь может отдельно включить её и задать диапазон;
- размытие от движения применяется только при включённой соответствующей настройке.

#### Реалистичный режим

- капля представляется эллипсом: базовое отношение полуосей у левой границы `q_left` однократно выбирается равномерно в диапазоне от 1,00 до 1,35 для каждой капли;
- угол поворота эллипса равномерно выбирается в диапазоне `[0°, 180°)`;
- угол остаётся постоянным для одной капли на всей траектории;
- отношение полуосей `q` линейно уменьшается от индивидуального `q_left` у левой границы до `1` у правой границы с сохранением площади и эквивалентного диаметра; левее левой границы используется `q_left`, правее правой — `1`; полная формула приведена в [правилах генерации, раздел 9](generation_rules.md#9-изменение-вытянутости-капли);
- используется готовый фиксированный вид: на светлом фоне контур тёмный и внутренняя область светлая, на тёмном полярность противоположная;
- отдельных регуляторов контура, заливки и общего вида нет; используется согласованный профиль `standard-v1`: внешние 20% нормированного радиуса — непрозрачный контур яркостью `0,10`, внутренность — яркость `0,95` с непрозрачностью `0,35` на светлом фоне; на тёмном собственные яркости инвертируются по `1-C`;
- для каждой капли случайно выбирается степень расфокусировки из заданного диапазона;
- степень расфокусировки остаётся постоянной для одной капли на всей траектории.

Эквивалентный диаметр эллипса определяется по площади:

```text
d_eq = 2 × sqrt(a × b)
```

где `a` и `b` — большая и малая полуоси. Для сохранения заданного `d_eq` полуоси рассчитываются так:

```text
a = d_eq / 2 × sqrt(q)
b = d_eq / 2 / sqrt(q)
```

### 6.2. Расфокусировка

Расфокусировка управляется отдельным переключателем `appearance.defocus_enabled`, независимо от размытия движения. В идеальном режиме по умолчанию выключена, в реалистичном включена; начальный диапазон — `0–2` пикселя. Пользователь задаёт `appearance.blur_sigma_min_px` и `appearance.blur_sigma_max_px` в пикселях: `0 <= min <= max`. При включённом эффекте для каждой новой капли значение выбирается равномерно из этого диапазона и сохраняется на траектории; равные границы дают фиксированное значение.

При выключенной расфокусировке в CSV записывается `blur_sigma_px=0`, даже если размытие движения включено. Заданный диапазон сохраняется в конфигурации. Нулевое значение сигмы не меняет изображение.

Размытие применяется к изображению конкретной капли до её композиции с фоном. В эталонной таблице сохраняется геометрический размер капли до оптического размытия. Нормированное гауссово ядро имеет радиус `ceil(4×sigma)`; правила обработки краёв и композиции определены в разделе 3 контракта. Явно загруженная настройка и переключение режима в существующей конфигурации не сбрасывают выбранную расфокусировку.

### 6.3. Выдержка и размытие от движения

Размытие от движения включается и выключается отдельным переключателем. При включении длина и направление следа рассчитываются по скорости капли и выдержке:

```text
motion_dx_px = Vx_m_s × exposure_us / scale_um_per_px
motion_dy_px = Vy_m_s × exposure_us / scale_um_per_px
motion_length_px = sqrt(motion_dx_px² + motion_dy_px²)
```

Интервал выдержки симметричен относительно `time_us` кадра. При включённом эффекте рендер учитывает и движение, и изменение формы реалистичной капли на протяжении выдержки, включая согласованное продолжение формы за границами кадра. В CSV записываются координаты и полуоси в середине выдержки до оптических эффектов. Законы расчёта приведены в [правилах генерации](generation_rules.md#92-изменение-формы-во-время-выдержки), временные отсчёты и растеризация `4×4` — в [контракте](configuration_contract.md#3-численные-правила-рендера).

При выключении эффекта выдержка сохраняется в конфигурации, но не влияет на изображение; используется геометрия в момент кадра.

### 6.4. Фон

Базовый фон однородный: каждый пиксель имеет одну и ту же яркость. Пользователь выбирает тёмный (`background.tone="dark"`, нормированная яркость `0,15`) или светлый (`background.tone="light"`, яркость `0,85`) фон. По умолчанию светлый. Ручного регулятора яркости нет.

Градиент, его направление и низкочастотная пространственная неоднородность исключены по ответу пользователя на вопрос 25. Базовая матрица создаётся один раз и одинакова на всех кадрах серии; сенсорный шум добавляется отдельно к готовому изображению согласно разделу 6.5.

### 6.5. Шум

1. Шум включается и выключается отдельным переключателем.
2. При выключенном шуме на всех кадрах используется неизменный базовый фон.
3. При включённом шуме для каждого кадра создаётся новая независимая шумовая составляющая и добавляется последней, после наложения всех капель на фон; шум действует и на области капель.
4. Пользователь регулирует интенсивность шума `background.noise_sigma` в нормированных единицах яркости; по умолчанию `0,02`, шум включён. При выключении значение сохраняется; нулевая сигма также означает отсутствие шума.
5. Распределение сенсорного шума — нормальное с нулевым средним.
6. После наложения капель и добавления шума яркость ограничивается к `[0,1]` и кодируется по формуле `floor(I×(2^bit_depth-1)+0,5)` без гамма-преобразования.

### 6.6. Перекрытия и границы

- перекрытия капель разрешены;
- каждая капля при перекрытии сохраняет собственную запись и ID;
- `overlap=true` устанавливается обеим каплям только при положительной общей площади их исходных проекций внутри кадра в момент середины выдержки; касание и пересечение только за пределами кадра не считаются перекрытием;
- капли накладываются по возрастанию `droplet_id`; капля с большим ID находится поверх предыдущих. Сенсорный шум добавляется после композиции капель и фона;
- `border=true` требует положительной площади исходной проекции внутри и снаружи кадра; касание края изнутри даёт `border=false`;
- полностью закрытая другой каплей проекция сохраняет собственные ID и строку CSV; две совпавшие проекции дают две строки и `overlap=true` у обеих;
- служебные контуры, ID и векторы допускаются только в окне предпросмотра и не попадают в экспортируемые изображения.

## 7. Требования к интерфейсу

Главное окно должно содержать логические группы:

1. **Серия и камера** — разрешение, число кадров, масштаб, межкадровый интервал, выдержка, формат и разрядность.
2. **Капли** — количество, тип и параметры распределения размеров, максимальный диаметр, уровень центральной концентрации.
3. **Скорость** — среднее, стандартное отклонение и границы модуля скорости, угловой разброс основной группы.
4. **Внешний вид** — идеальный/реалистичный режим, отдельное включение и диапазон гауссовой расфокусировки. Готовый вид автоматически зависит от тона фона; регуляторов контура, заливки и общего вида нет.
5. **Фон и шум** — выбор однородного тёмного или светлого фона, включение и интенсивность шума.
6. **Случайная генерация** — текущее значение `seed` и кнопка создания нового значения.
7. **Предпросмотр** — чистый кадр и переключатель служебного слоя.
8. **Экспорт** — папка назначения, запуск, прогресс и отмена.

В предпросмотре служебный слой должен уметь показывать:

- ID капель;
- геометрические контуры до размытия;
- векторы скорости;
- выделение граничных капель.

Интерфейс не должен зависать во время генерации. Должны отображаться:

- число готовых кадров и общее число кадров;
- процент выполнения;
- прошедшее время;
- текущий статус;
- кнопка «Отмена».

## 8. Проверка входных данных

Перед предпросмотром и запуском генерации программа должна проверять:

- число кадров и капель;
- принадлежность разрешения списку пресетов;
- положительность масштаба и временных параметров;
- условие `exposure_us <= frame_interval_us`;
- корректность параметров нормального или логнормального распределения;
- выполнение условия минимального диаметра 3 пикселя;
- корректность максимального диаметра;
- неотрицательность стандартных отклонений;
- положительность минимального модуля скорости, правильный порядок его границ и неотрицательность углового разброса основной группы;
- корректность диапазона расфокусировки и интенсивности шума;
- диапазон `seed`, конечность чисел и производных размеров, времени и перемещений;
- правила нулевого разброса, совпадающих границ и достижимости фиксированных значений по разделам 4–6 правил генерации.

Перед экспортом дополнительно проверяются выбранная папка, права записи и свободное место. Для предпросмотра папка не требуется. Допустимый нулевой разброс используется без случайной выборки; недопустимый выявляется до запуска. Для диаметра, модуля скорости и угла основной группы действует лимит 100 000 неудачных попыток получить одно значение; исчерпание лимита завершает операцию ошибкой без обрезания значений или пропуска капель.

При ошибке генерация не запускается. Пользователь получает сообщение на русском языке с названием параметра и причиной ошибки.

## 10. Формат результатов

### 10.1. Структура папки

Для каждой серии создаётся отдельная папка:

```text
series_YYYYMMDD_HHMMSS_seed/
├── frames/
│   ├── frame_000001.png
│   ├── frame_000002.png
│   └── ...
├── droplets.csv
└── config.json
```

Для TIFF используется расширение `.tif`; номер кадра содержит ровно шесть цифр. При совпадении имени папки серии добавляется первый свободный суффикс `_001`, `_002` и далее; существующая серия не перезаписывается.

### 10.2. Изображения

- все кадры одной серии имеют одинаковое разрешение, формат и разрядность;
- PNG сохраняется без потерь с уровнем сжатия 6, TIFF — без сжатия;
- для 8-битных изображений допустимый диапазон — 0–255;
- для 16-битных изображений допустимый диапазон — 0–65535;
- изображения одноканальные, в градациях серого;
- экспортируемые изображения не содержат альфа-канала, служебной разметки и меняющихся временных метаданных.

### 10.3. Файл `droplets.csv`

Кодировка — UTF-8 без BOM, разделитель — запятая, десятичный разделитель — точка, конец строки — LF. Для каждой геометрически активной капли на каждом полностью зафиксированном кадре создаётся отдельная строка, включая полностью закрытые проекции. Строки сортируются по номеру кадра, затем ID. ID начинаются с 1 и выдаются последовательно без повторного использования; на первом кадре все капли имеют `is_new=true`.

Булевы значения записываются как `true`/`false`, целые — десятичными цифрами, `float64` — в формате `.17g` (до 17 значащих цифр, научная запись разрешена); `-0` нормализуется в `0`. Порядок столбцов соответствует следующей таблице и разделу 4 контракта.

Обязательные столбцы:

| Столбец | Тип | Описание |
|---|---|---|
| `frame_number` | int | Номер кадра, начиная с 1 |
| `time_us` | float | Время кадра относительно начала серии, мкс |
| `droplet_id` | int | Уникальный ID капли |
| `is_new` | bool | Первый кадр присутствия данной капли |
| `center_x_px` | float | Координата центра X, пиксели |
| `center_y_px` | float | Координата центра Y, пиксели |
| `center_x_mm` | float | Координата центра X, мм |
| `center_y_mm` | float | Координата центра Y, мм |
| `diameter_eq_px` | float | Эквивалентный диаметр, пиксели |
| `diameter_eq_um` | float | Эквивалентный диаметр, мкм |
| `semi_major_px` | float | Большая геометрическая полуось в середине выдержки, пиксели |
| `semi_minor_px` | float | Малая геометрическая полуось в середине выдержки, пиксели |
| `angle_deg` | float | Угол эллипса относительно оси X, градусы |
| `vx_m_s` | float | Горизонтальная компонента скорости, м/с |
| `vy_m_s` | float | Вертикальная компонента скорости, м/с |
| `speed_m_s` | float | Модуль скорости, м/с |
| `blur_sigma_px` | float | Степень расфокусировки капли |
| `border` | bool | Признак пересечения границы кадра |
| `overlap` | bool | Положительная общая площадь с другой каплей внутри кадра до размытия |

Пересчёт координат:

```text
center_x_mm = center_x_px × scale_um_per_px / 1000
center_y_mm = center_y_px × scale_um_per_px / 1000
```

В идеальном режиме всегда `semi_major_px = semi_minor_px = diameter_eq_px / 2` и `angle_deg = 0`. При выключенной гауссовой расфокусировке `blur_sigma_px = 0`; при включённой записывается выбранная для капли сигма, независимо от переключателя размытия движения.

### 10.4. Файл `config.json`

Экспортируемый файл должен содержать:

- все введённые пользователем параметры;
- фактически использованный `seed`;
- версию программы и версию схемы конфигурации;
- выбранную корневую папку экспорта и формат изображений;
- `run.started_at` — время начала с часовым поясом;
- `run.output_directory` — фактическую папку серии;
- `run.status` — `running` во время работы, итоговый `completed`, `cancelled` или `error`;
- `run.completed_frame_count` — число полностью зафиксированных кадров;
- `run.environment` — сборку программы, ОС, процессор, среду исполнения, зависимости, кодеки и численный профиль по разделу 5 контракта.

## 11. Отмена и обработка ошибок

1. Нажатие «Отмена» должно останавливать процесс после завершения текущей безопасной операции записи.
2. Уже записанные кадры не удаляются автоматически.
3. Папка незавершённой серии сохраняется, а в `config.json` записываются `run.status="cancelled"` и фактическое `run.completed_frame_count`. При ошибке используется `run.status="error"`.
4. Повреждённый или не полностью записанный текущий файл кадра должен быть удалён или перезаписан атомарно.
5. При исключении программа должна сохранить диагностическую запись в локальный журнал и показать пользователю понятное сообщение.
6. Ошибка одного кадра не должна приводить к молчаливому созданию серии с неверной разметкой.

## 12. Нефункциональные требования

- жёсткое ограничение времени генерации не устанавливается;
- интерфейс должен оставаться отзывчивым во время генерации;
- прогресс и возможность отмены обязательны;
- одинаковые настройки генерации и `seed` при одной сборке, версиях среды, зависимостей, кодеков и вычислительном окружении должны давать побайтово идентичные изображения и CSV; при изменении окружения гарантия снимается с предупреждением;
- расчёты координат, скоростей и промежуточной яркости выполняются в `float64` без промежуточного округления до целых пикселей;
- предпросмотр не расходует состояние будущего экспорта, а включение шума не изменяет геометрию и CSV;
- округление допускается только при растеризации изображения и сериализации с достаточным числом знаков;
- программа должна проверять свободное место перед генерацией крупной серии и предупреждать пользователя о возможном большом объёме данных;
- все рабочие файлы, настройки и журналы хранятся локально;
- сетевой доступ для выполнения основных функций не требуется.

## 13. Критерии приёмки

Программа считается соответствующей ТЗ при выполнении следующих проверок.

1. **Запуск:** приложение запускается в Windows 10/11 x64 через `run.bat` без обращения к интернету.
2. **Диапазоны:** успешно создаются серии с 2 и 1000 кадрами, а также с 1 и 10 000 каплями на кадр при допустимых остальных параметрах.
3. **Разрешения:** каждый из четырёх пресетов создаёт изображения точного требуемого размера.
4. **Форматы:** файлы корректно читаются как одноканальные PNG 8 бит, PNG 16 бит и TIFF 16 бит.
5. **Количество:** для каждого полностью сформированного кадра в `droplets.csv` присутствует ровно заданное число строк.
6. **Траектории:** для капель с одинаковым ID координаты соседних кадров соответствуют заданным `Vx`, `Vy`, масштабу и межкадровому интервалу с абсолютной погрешностью не более `0,01` пикселя в эталонных данных.
7. **ID:** ID сохраняется до полного выхода капли из кадра и не используется повторно для новой капли.
8. **Размер:** эквивалентный диаметр рассчитанной геометрии совпадает со значением в CSV с относительной погрешностью не более 0,1% до растеризации.
9. **Минимальный размер:** в серии отсутствуют капли с эквивалентным диаметром менее 3 пикселей.
10. **Границы:** частично видимые капли присутствуют в кадре и корректно помечены `border=true`.
11. **Перекрытия:** перекрывающиеся капли не объединяются в эталонных данных и получают `overlap=true`.
12. **Размытие движения:** на изолированном идеальном круге вдали от границ, без шума и расфокусировки протяжённость растрового покрытия вдоль движения минус диаметр отличается от расчётной длины пути не более чем на 1 пиксель; покрытие измеряется до целочисленного квантования по разделу 3 контракта.
13. **Статичный фон:** при выключенном шуме значения пикселей фона вне областей, затронутых каплями, одинаковы на всех кадрах.
14. **Шум:** при включённом шуме базовая структура фона сохраняется, а шумовая составляющая различается между кадрами.
15. **Чистый экспорт:** ID, контуры и векторы видны в режиме предпросмотра, но отсутствуют в экспортируемых изображениях.
16. **Повторяемость:** повторная генерация с теми же настройками и `seed` в одинаковом окружении по разделу 6 контракта создаёт побайтово одинаковые кадры и CSV, включая повтор после предпросмотра. Служебные время, путь, статус и счётчик в `config.json` могут различаться; изменение окружения вызывает предупреждение об отсутствии гарантии точного повтора.
17. **Конфигурация:** сохранённый JSON открывается, восстанавливает параметры и позволяет повторить серию.
18. **Отмена:** отмена не блокирует интерфейс, не повреждает готовые файлы и устанавливает статус `cancelled`.
19. **Валидация:** некорректные значения блокируют запуск и сопровождаются понятным сообщением на русском языке.

Для статистической проверки распределений используется серия, содержащая не менее 10 000 вновь созданных капель, с параметрами, удалёнными от границ усечения:

- для нормального распределения абсолютное отклонение выборочного среднего от `μd` не должно превышать `0,05 × σd`, а относительное отклонение выборочного стандартного отклонения от `σd` — 5%;
- для логнормального распределения относительное отклонение выборочной медианы от `d50` не должно превышать 3%, а относительное отклонение выборочного геометрического стандартного отклонения от `σg` — 5%;
- для модуля скорости абсолютное отклонение выборочного среднего не должно превышать `0,05 × speed_std_m_s`, относительное отклонение выборочного стандартного отклонения — 5%; при нулевом разбросе проверяется фиксированное значение;
- все выборочные значения должны находиться внутри заданных границ.

Компоненты `Vx` и `Vy` проверяются по формулам из модуля и угла и не обязаны иметь независимые нормальные распределения. Для углов основной группы проверяется усечённое нормальное распределение, для абсолютных углов выбросов — равномерное в `(30°, 90°)`. Частота выбросов оценивается по новым ID с вероятностью создания 5%; точная доля на каждом кадре не требуется. Полные основания проверок приведены в разделе 8 правил генерации.

## 15. Ограничения текущей версии

В текущую версию не входят:

- физическое моделирование распыла и газожидкостного потока;
- ускорение капель;
- столкновение, коалесценция и дробление;
- трёхмерное движение и восстановление глубины;
- автоматическая подгонка синтетических параметров по реальным изображениям;
- загрузка реального фона;
- цветные RGB-изображения;
- генерация видеофайла;
- экспорт масок сегментации;
- распознавание или анализ сгенерированных изображений;
- прямая интеграция с программой анализа распыла.

Перекрытия в текущей версии являются только эффектом наложения двумерных проекций и не моделируют физическое взаимодействие капель.
