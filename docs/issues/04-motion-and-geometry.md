# Реализовать траектории, замену вышедших капель и признаки border/overlap

## Цель и текущее состояние

Поддерживать непрерывные траектории и точное заданное количество капель на каждом кадре. Модель серии реализована локально; рендер и экспорт относятся к последующим задачам.

## Результат реализации — 15.09.2026 (локально)

- `generation.generate_frames` выдаёт кадры с неизменяемыми состояниями, временем,
  актуальными полуосями и признаками `is_new`, `border`, `overlap`.
- `DropletSampler.sample_replacement` создаёт каплю слева и продолжает RNG и ID.
- `geometry/projections.py` проверяет активность, границы и общую площадь внутри
  кадра. Для отбора пар используется пространственная сетка; окончательная проверка
  использует аналитические сечения эллипсов и численную минимизацию выпуклого зазора.
- `.venv/Scripts/python.exe -m unittest discover -s tests -v`: **60 тестов прошли**,
  включая 21 новый тест в `tests/test_geometry.py` и `tests/test_sequence.py`.
  Проверены отдельные сценарии 1000 кадров и массовой замены 10 000 капель.

API, порядок замены и допуск float64 описаны в [README](../../README.md#модель-серии-и-геометрия-4).
Изменения пока локальные; статус GitHub #4 не изменён. Сквозной рендер и CSV — D05–D06;
полная нагрузочная приёмка с рендером — D09.

## Объём работ

- Рассчитывать движение в экранных координатах: `dx=Vx*frame_interval_us/scale_um_per_px`, аналогично для `dy`; время — `(frame_number-1)*frame_interval_us`.
- Использовать `float64` без промежуточного округления до пикселей по [контракту D01](../configuration_contract.md).
- Использовать непрерывную область `[0, W] × [0, H]` с центрами пикселей `(j+0,5; i+0,5)` при нумерации строк и столбцов с нуля.
- Сохранять ID и постоянные индивидуальные параметры до полного выхода геометрии капли по правилам D01. Текущие `q` и полуоси реалистичной капли пересчитывать по её горизонтальному положению согласно [линейному закону округления](../generation_rules.md#9-изменение-вытянутости-капли), сохраняя эквивалентный диаметр.
- В том же кадре заменять вышедшую каплю новой с уникальным, ранее не использовавшимся ID. ID начинаются с 1 и выдаются последовательно.
- Заменяющие капли обеих групп создавать на левой границе (`center_x_px=0`); Y выбирать нормально вокруг `H/2` с разбросом выбранного уровня концентрации и повторной выборкой за пределами стороны согласно D01.
- Формировать `is_new`, `border`, `overlap` для кругов и повёрнутых эллипсов. `overlap` требует положительной общей площади пары внутри кадра; касания и пересечения только снаружи не считаются перекрытием. Перекрытия не объединяют записи и не вызывают физического взаимодействия.
- Предусмотреть пространственный поиск кандидатов на пересечение; ограничивающие прямоугольники не считать окончательным доказательством пересечения эллипсов.

## Пример

При `Vx=2 м/с`, `Vy=-1 м/с`, интервале `100 мкс` и масштабе `10 мкм/пиксель` координата `(100,100)` на следующем кадре становится `(120,90)`. ID, эквивалентный диаметр и скорость сохраняются, если капля остаётся в кадре; текущие полуоси реалистичной капли пересчитываются по новому положению.

## Критерии готовности

- [x] Каждый кадр содержит ровно заданное число геометрически активных капель, включая полностью закрытые проекции и кадры массового выхода. Касание края изнутри даёт `border=false`, касание снаружи без площади внутри требует замены.
- [x] Погрешность координат сохраняющегося ID не превышает 0,01 пикселя.
- [x] ID не переиспользуются; `is_new` истинен только на первом кадре присутствия, включая начальные капли.
- [x] Проверены геометрические случаи четырёх сторон, углы и касания, а для согласованной модели движения — выходы вправо, вверх и вниз, оба знака `Vy`, `Vy=0` и замена вышедших капель на левой границе. Нулевой полный модуль скорости отклоняется валидацией согласно D01.
- [x] Проверены пересечение, отсутствие пересечения и вложенность проекций внутри кадра; пересекающиеся капли получают `overlap=true`. Для двух частично видимых проекций с общей площадью только снаружи кадра `overlap=false` при отсутствии других соседей.
- [x] Для `q_left=1,30` значения `q` у левой границы, в середине и у правой границы равны соответственно `1,30`, `1,15`, `1,00`; площадь сохраняется, `border` и `overlap` учитывают актуальные полуоси в момент кадра.
- [x] Граничные капли учитываются до полного выхода, а замена не меняет параметры оставшихся капель.
