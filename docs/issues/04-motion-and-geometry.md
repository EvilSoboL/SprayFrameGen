# Реализовать траектории, замену вышедших капель и признаки border/overlap

## Цель и текущее состояние

Поддерживать непрерывные траектории и точное заданное количество капель на каждом кадре. Это требуемое поведение ТЗ; действующего движка в репозитории нет.

## Объём работ

- Рассчитывать движение в экранных координатах: `dx=Vx*frame_interval_us/scale_um_per_px`, аналогично для `dy`; время — `(frame_number-1)*frame_interval_us`.
- Использовать плавающую точку без промежуточного округления до пикселей.
- Сохранять ID и индивидуальные параметры до полного выхода геометрии капли по правилам D01.
- В том же кадре заменять вышедшую каплю новой с уникальным, ранее не использовавшимся ID.
- Выбирать входную сторону по средним компонентам скорости согласно ТЗ; центр новой капли размещать на границе, вторую координату выбирать с учётом концентрации.
- Формировать `is_new`, `border`, `overlap` для кругов и повёрнутых эллипсов. Перекрытия не объединяют записи и не вызывают физического взаимодействия.
- Предусмотреть пространственный поиск кандидатов на пересечение; ограничивающие прямоугольники не считать окончательным доказательством пересечения эллипсов.

## Пример

При `Vx=2 м/с`, `Vy=-1 м/с`, интервале `100 мкс` и масштабе `10 мкм/пиксель` координата `(100,100)` на следующем кадре становится `(120,90)`. ID и параметры капли сохраняются, если она остаётся в кадре.

## Критерии готовности

- [ ] Каждый кадр содержит ровно заданное число активных капель, включая кадры массового выхода.
- [ ] Погрешность координат сохраняющегося ID не превышает 0,01 пикселя.
- [ ] ID не переиспользуются; `is_new` истинен только на первом кадре присутствия, включая начальные капли.
- [ ] Проверены выходы через четыре стороны, углы, касания, отрицательные и нулевые скорости.
- [ ] Проверены пересечение, отсутствие пересечения и вложенность проекций; пересекающиеся капли получают `overlap=true`.
- [ ] Граничные капли учитываются до полного выхода, а замена не меняет параметры оставшихся капель.
