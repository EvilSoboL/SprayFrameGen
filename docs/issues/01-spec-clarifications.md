# Уточнить математические и визуальные правила генерации перед разработкой

## Цель и контекст

Зафиксировать неоднозначные правила ТЗ, влияющие на геометрию, эталонные данные и повторяемость. Это исследовательская задача: результатом должны быть согласованные решения, без реализации приложения.

## Текущее состояние

- По ТЗ требуется точное количество видимых капель, корректные `border` и `overlap`, размытие движения и воспроизводимость.
- Проверено по документу: не определены временная привязка выдержки, учёт размытия при проверке видимости и закон распределения `q`. Полного перечня параметров внешнего вида в примере JSON нет.
- Исходного кода приложения нет. Указанные в ТЗ `Img000001.jpg`–`Img000006.jpg` в рабочем дереве не найдены.

## Объём работ и ожидаемый результат

Зафиксировать в ТЗ или отдельной спецификации:

1. Геометрическую область кадра, правила касания границы, выхода капли, `border` и `overlap`, включая полностью перекрытые капли. Предложение для согласования: использовать геометрию до размытия и считать активной каждую проекцию, пересекающую кадр, даже если она закрыта другой каплей.
2. Координату и время CSV относительно интервала выдержки. Предложение: координата в середине выдержки и симметричный след; это ещё не утверждённое требование.
3. Поведение при `σ = 0`, `σg = 1`, равных границах и недостижимом диапазоне; обработку крайне малой вероятности принятия при повторной выборке без зависания и без обрезания значений.
4. Распределение `q`, правила расфокусировки идеального режима, параметры и диапазоны контура, заливки и низкочастотной неоднородности, порядок композиции и добавления шума.
5. Полные поля JSON, значения по умолчанию, точность CSV, запись булевых значений, допустимый диапазон `seed` и границы гарантии повторяемости окружения.
6. Правила координаты вдоль входной границы и появления при нулевых средних скоростях. Не менять заданное ТЗ правило выбора стороны по средним скоростям без согласования.

Получить доступ к визуальным референсам или явно оставить сравнение с ними незавершённой зависимостью D06. Не подменять их вымышленными примерами.

## Критерии готовности

- [ ] Каждая неоднозначность имеет явное решение либо помечена как открытый вопрос с указанием заблокированного этапа.
- [ ] Решения, меняющие наблюдаемое поведение, согласованы с пользователем.
- [ ] Указаны допустимые вырожденные случаи и ошибки валидации.
- [ ] Подготовлены примеры определения времени, видимости, границ и пересечений.
- [ ] Полный список параметров пригоден для реализации D02 без дополнительных догадок.
