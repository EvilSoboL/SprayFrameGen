# Создать каркас приложения и полную JSON-конфигурацию с валидацией

## Цель и текущее состояние

Создать единую модель настроек, используемую генератором и будущим интерфейсом. В D01 согласованы [полный контракт](../configuration_contract.md) и [стартовый JSON](../examples/config.default.json). Каркас уже присутствовал в рабочем дереве при начале этой работы; 15.09.2026 он проверен по критериям D02 и дополнен обработкой ошибок запуска и тестами CLI. По поручению пользователя результат опубликован в [issue #2](https://github.com/EvilSoboL/SprayFrameGen/issues/2), задача закрыта с причиной `completed`. Описания #3–#10 обновлены, публикация проверена повторным чтением. Последние правки кода и новые тесты остаются в рабочем дереве; коммит и push не выполнялись.

## Объём работ

- Выбрать и зафиксировать стек с учётом Windows x64, офлайн-работы, русскоязычного GUI и одноканальных 16-битных изображений; подготовить структуру проекта и зависимости.
- Добавить начальную точку входа и `run.bat` для запуска каркаса в подготовленном локальном окружении; окончательное оформление поставки относится к D10.
- Разделить конфигурацию, модель капель, геометрию и движение, рендер, экспорт, управление генерацией и интерфейс.
- Реализовать все поля, типы, начальные значения и ограничения раздела 1 контракта D01; сохранять обе группы параметров размеров и остальные неактивные настройки. `seed` — целое число от 0 до 4294967295, новый автоматически создаётся, явный сохраняется.
- Для движения использовать `speed_mean_m_s`, `speed_std_m_s`, `speed_min_m_s`, `speed_max_m_s` и `direction_std_deg` (по умолчанию `10°`). Раздельные настройки распределений `Vx` и `Vy` заменены модулем и направлением; валидировать положительность минимального модуля, неотрицательный разброс и вырожденные случаи по D01.
- Сохранять отдельные `appearance.defocus_enabled`, `appearance.blur_sigma_min_px`, `appearance.blur_sigma_max_px`. Для новой конфигурации идеального режима расфокусировка по умолчанию выключена; загруженное явное значение сохраняется. Валидировать `0 <= min <= max`, разрешая равные границы.
- Для фона использовать `background.tone` (`dark`/`light`), включение и интенсивность шума. Тона фиксированы на `0,15` и `0,85`, по умолчанию светлый. Параметры градиента и низкочастотной неоднородности исключены. Готовый вид капли автоматически меняет полярность с тоном фона; регуляторов контура, заливки и общего вида нет.
- Реализовать загрузку и сохранение JSON; метаданные отделить в `run` по разделу 5 контракта, до запуска использовать `null`. Записывать фактическую версию программы вместо условной версии примера. Несовместимые схемы и профили отклонять; при различии сборки или окружения предупреждать об отсутствии гарантии точного повтора.
- Зафиксировать алгоритм генератора случайных чисел и способ независимых потоков модели и шума вместе с версиями зависимостей и идентификатором сборки; соблюдать раздел 6 контракта.
- Реализовать единый валидатор чисел, диапазонов, совместимости формата и разрядности. Отклонять `NaN` и бесконечности, не допускающие корректных расчётов.
- Неизвестные совместимые поля игнорировать с предупреждением; отсутствие обязательных полей сообщать как ошибку.
- Возвращать русские сообщения с названием поля и причиной. Проверку реального места и прав экспорта интегрировать в D07.

## Критерии готовности

- [x] Сохранение и загрузка сохраняют все параметры, включая `seed` и оптические эффекты.
- [x] Ручной ввод и JSON используют одни правила проверки.
- [x] Поддержаны только четыре разрешения и три сочетания формата/разрядности из ТЗ.
- [x] Ошибки масштаба, времени, размеров, скоростей и расфокусировки обнаруживаются до вычислений.
- [x] Например, `exposure_us=101` при `frame_interval_us=100` вызывает понятную ошибку.
- [x] Есть автоматические проверки загрузки, сохранения, отсутствующих и неизвестных полей, совместимости версии/профиля, границ seed, конечности производных значений и вырожденных случаев D01.
- [x] Начальные настройки совпадают с согласованным JSON; импорт и переключение режима не сбрасывают явные настройки расфокусировки. Невыбранная папка не блокирует валидацию настроек для будущего предпросмотра; сам рендер предпросмотра относится к D05–D08.

## Результат и проверка от 15.09.2026

- Стек: CPython 3.14.0 x64, Tkinter 8.6.15, NumPy 2.3.5, Pillow 12.0.0; версии зависимостей закреплены в `requirements.txt` и `pyproject.toml`.
- [Конфигурация](../../sprayframegen/configuration.py): dataclass-модели, единый валидатор ручных изменений и JSON, все поля и метаданные, предупреждения совместимости.
- [Окружение](../../sprayframegen/environment.py) и [случайные потоки](../../sprayframegen/generation/random_streams.py): фактические версии, хеш исходников сборки, PCG64 и два независимых потока SeedSequence для модели и шума.
- [Точка входа](../../sprayframegen/__main__.py), [начальное окно](../../sprayframegen/ui/app.py) и [run.bat](../../run.bat) работают; ошибки недоступного Tcl/Tk обрабатываются без traceback. Окончания строк launcher закреплены как CRLF, сообщения — русские.
- `python -m unittest discover -s tests -v`: 28 тестов прошли, включая [конфигурацию](../../tests/test_configuration.py), [метаданные/RNG/кодеки](../../tests/test_runtime.py) и [CLI](../../tests/test_cli.py).
- `python -m unittest discover -s tests -p ui_smoke.py -v`: отдельный тест окна прошёл вне ограничений песочницы; проверены создание, редактирование, сохранение, загрузка и сообщение об ошибке.
- `run.bat --check docs/examples/config.default.json`, `run.bat --smoke-test` и `pip check` выполнены успешно. Тест launcher проверяет также отсутствие окружения в папке с кириллицей и пробелами.

Проверено на Windows 10 x64. Генерация капель, экспорт серии, полный GUI и проверка поставки на Windows 11 выполняются в следующих задачах; сохранность 16-битных значений подтверждена только отдельной проверкой выбранных кодеков.
