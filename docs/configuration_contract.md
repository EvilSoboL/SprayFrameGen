# Контракт конфигурации, рендера и экспорта

**Статус:** согласовано 14.09.2026 ответами на вопросы 31–33. Документ дополняет решения 1–30 из [правил генерации](generation_rules.md) и является частью результата issue №1. Реализация приложения в эту задачу не входит.

Согласованы три части: стартовые настройки (вопрос 31), фиксированный вид капли (вопрос 32), технический контракт (вопрос 33). [Полный JSON](examples/config.default.json) представляет новые настройки до запуска; это не результат выполненной генерации.

## 1. Стартовые настройки и поля JSON

Для новой конфигурации используются 20 кадров по 100 капель, `640×480`, PNG 8 бит, реалистичный режим, светлый фон, включённые шум и размытие движения. Масштаб — `10` мкм/пиксель, интервал — `100` мкс, выдержка — `20` мкс. Размеры логнормальные с медианой `120` мкм и геометрическим стандартным отклонением `1,35`; нормальный модуль скорости имеет среднее `8` м/с и стандартное отклонение `0,8` м/с.

Все поля из таблиц обязательны в сохраняемом JSON, включая неактивные настройки. Значения по умолчанию применяются при создании новой конфигурации, а не вместо отсутствующих полей при импорте. Загруженные явные значения сохраняются. Числа должны быть конечными; `NaN`, бесконечность и логические значения вместо чисел недопустимы. Целочисленные поля не принимают дробные значения или строки.

### Общие поля

| Поле | Тип | Начальное значение и правило |
|---|---|---|
| `schema_version` | string | `"1.0"`; версия структуры и смыслов полей |
| `program_version` | string | Непустая фактическая версия сохраняющей программы; `"0.1.0"` в примере — обозначение будущей версии, а не утверждение о существующем выпуске |
| `seed` | integer | Автоматически выбирается из `[0, 4294967295]`; допускается ручной ввод. `123456789` — фиксированный seed примера |
| `camera`, `droplets`, `motion`, `appearance`, `background`, `export` | object | Полные группы настроек из таблиц ниже |
| `run` | object или null | `null` до запуска; метаданные сформированной или незавершённой серии по разделу 5 |

### `camera`

| Поле | Тип | По умолчанию | Допустимые значения |
|---|---|---:|---|
| `width_px` | integer | 640 | Вместе с высотой только `640×480`, `1024×768`, `1280×1024`, `1920×1080` |
| `height_px` | integer | 480 | Та же проверка пары |
| `scale_um_per_px` | number | 10 | `> 0`, мкм/пиксель |
| `frame_count` | integer | 20 | От 2 до 1000 включительно |
| `frame_interval_us` | number | 100 | `> 0`, мкс |
| `exposure_us` | number | 20 | `0 < exposure_us <= frame_interval_us` |
| `format` | string | `"png"` | `"png"` или `"tiff"` |
| `bit_depth` | integer | 8 | `png`: 8 или 16; `tiff`: только 16 |

### `droplets`

| Поле | Тип | По умолчанию | Допустимые значения |
|---|---|---:|---|
| `count_per_frame` | integer | 100 | От 1 до 10 000 включительно |
| `size_distribution` | string | `"lognormal"` | `"normal"` или `"lognormal"` |
| `mean_um` | number | 120 | Среднее исходного нормального распределения; конечное число |
| `std_um` | number | 20 | `>= 0` |
| `median_um` | number | 120 | Медиана исходного логнормального распределения, `> 0` |
| `geometric_std` | number | 1.35 | `>= 1` |
| `max_diameter_um` | number | 500 | `>= 3 × camera.scale_um_per_px` |
| `concentration` | string | `"medium"` | `"low"`, `"medium"`, `"high"` |
| `render_mode` | string | `"realistic"` | `"ideal"` или `"realistic"` |

Обе группы параметров размера сохраняются при переключении закона. Типы и простые ограничения проверяются у обеих групп; проверка достижимости диапазона и вырожденного распределения применяется к выбранному закону. При ненулевом разбросе среднее/медиана исходного распределения не обязаны находиться в допустимом диапазоне. Действуют согласованные повторная выборка, предел 100 000 неудач и правила нулевого разброса из разделов 4–6 правил генерации.

Минимальные `3` пикселя относятся к эквивалентному диаметру проекции, а не к каждой из осей эллипса. При начальном масштабе нижняя граница равна `30` мкм.

### `motion`

| Поле | Тип | По умолчанию | Допустимые значения |
|---|---|---:|---|
| `speed_mean_m_s` | number | 8 | Среднее исходного нормального распределения модуля; конечное число |
| `speed_std_m_s` | number | 0.8 | `>= 0` |
| `speed_min_m_s` | number | 4 | `> 0` |
| `speed_max_m_s` | number | 12 | `>= speed_min_m_s` |
| `direction_std_deg` | number | 10 | `>= 0`, градусы |
| `motion_blur_enabled` | boolean | true | Включение временного усреднения |

Нулевой разброс, равные границы и недостижимый диапазон проверяются по правилам генерации. `Vx` и `Vy` вычисляются из модуля и угла; отдельных настроек их распределений нет.

### `appearance`

| Поле | Тип | По умолчанию | Допустимые значения |
|---|---|---:|---|
| `profile` | string | `"standard-v1"` | Только этот фиксированный профиль в первой версии; служебный идентификатор, без регулятора в GUI |
| `defocus_enabled` | boolean | true | Для новой конфигурации реалистичного режима — true, идеального — false |
| `blur_sigma_min_px` | number | 0 | `>= 0` |
| `blur_sigma_max_px` | number | 2 | `>= blur_sigma_min_px` |

Равные границы разрешены. При выключенной расфокусировке они сохраняются, но фактическая сигма в модели и CSV равна нулю. Обычное переключение режима в существующей конфигурации не сбрасывает явно выбранную расфокусировку; начальные значения применяются при создании новой конфигурации соответствующего режима.

### `background` и `export`

| Поле | Тип | По умолчанию | Допустимые значения |
|---|---|---:|---|
| `background.tone` | string | `"light"` | `"dark"` или `"light"`; яркости `0,15` и `0,85` соответственно |
| `background.noise_enabled` | boolean | true | Включение сенсорного шума |
| `background.noise_sigma` | number | 0.02 | `>= 0`, стандартное отклонение в нормированном диапазоне яркости; не в целых отсчётах PNG |
| `export.output_directory` | string или null | null | Выбранная пользователем абсолютная папка для серий; null, пока она не выбрана |

При выключенном шуме его интенсивность сохраняется. Сигма шума `0` также даёт отсутствие шума. Папка не требуется для предпросмотра; экспорт требует существующую доступную для записи папку. Путь к референсам не становится папкой экспорта автоматически.

Предварительная валидация также проверяет конечность производных размеров, перемещений и времени последнего кадра. Числовое переполнение — понятная ошибка до генерации, а не основание обрезать значение. Недостаток памяти и ошибки записи обрабатываются по D07; произвольные молчаливые ограничения параметров не добавляются.

### Фиксированные правила вне пользовательских настроек

Концентрации соответствуют коэффициентам `0,45`, `0,30`, `0,18` от размеров кадра. Доля выбросов при создании — `0,05`, угловой порог — `30°`, предел абсолютного угла выброса — строго `90°`, `q_left` равномерно в `[1, 1,35]`. Замены входят слева. Начальное распределение координат, округление, геометрические признаки и временная привязка заданы в правилах генерации. Эти константы и правила входят в версию модели программы; они не требуют дополнительных полей GUI.

## 2. Фиксированный вид `standard-v1`

Это воспроизводимая приближённая модель вида капли по просмотренным референсам. Численные яркости, толщина и прозрачность не измерялись по фотографиям. Визуальная проверка реализованного рендера остаётся отдельной работой D06 и D09.

В локальных координатах эллипса `u`, `v` задаётся нормированный радиус `rho = sqrt((u/a)^2 + (v/b)^2)`. Полуоси и поворот берутся из геометрии в соответствующий момент времени. `C` — собственная нормированная яркость слоя, `A` — его непрозрачность.

| Режим и область | Яркость `C` на светлом фоне | Непрозрачность `A` |
|---|---:|---:|
| Идеальная капля, `rho <= 1` | 0.10 | 1 |
| Реалистичный контур, `0.8 < rho <= 1` | 0.10 | 1 |
| Реалистичная внутренняя область, `rho <= 0.8` | 0.95 | 0.35 |
| Вне капли, `rho > 1` | Не влияет | 0 |

Контур занимает внешние 20% нормированного радиуса. На тёмном фоне применяется `C_dark = 1 - C_light`, непрозрачность остаётся прежней. Толщина, яркости и прозрачность не регулируются пользователем. Смена полярности применяется и к контрастной заливке идеального режима.

До оптических эффектов рассчитывается `P = A × C`. Усреднение по времени, растеризация и гауссово размытие применяются к `P` и `A` одинаково. После этого слой накладывается по формуле `I_next = P + (1 - A) × I_previous`. Слои идут по возрастанию ID; шум добавляется после них. Такой порядок определяет поведение полупрозрачных пересечений однозначно.

Пример без размытия и шума: внутри одиночной реалистичной капли на светлом фоне яркость равна `0,35 × 0,95 + 0,65 × 0,85 = 0,885`, контур — `0,10`, фон — `0,85`. На тёмном фоне соответствующие значения равны `0,115`, `0,90` и `0,15`. Это расчёт профиля, а не результат готового приложения.

## 3. Численные правила рендера

Координаты, физические величины и промежуточные значения яркости вычисляются в `float64`. Геометрические признаки определяются до растеризации. Их нельзя выводить из масок с учётом шума, порога яркости или расфокусировки.

### Растеризация и выдержка

Для сглаживания каждый пиксель использует сетку `4×4` равновесных отсчётов. Для столбца `j`, строки `i` и индексов `k,l` от 0 до 3 точки равны `(j + (k+0,5)/4, i + (l+0,5)/4)`. Пиксельные `P` и `A` — среднее этих отсчётов.

При выключенном размытии движения используется только середина выдержки. При включённом выполняется равномерное усреднение по средним точкам временных отрезков. Число отсчётов для каждой капли определяется её перемещением и изменением формы:

```text
dx = vx_m_s × exposure_us / scale_um_per_px
dy = vy_m_s × exposure_us / scale_um_per_px
L = sqrt(dx² + dy²)
Dq = (q_left - 1) × abs(dx) / width_px
S = diameter_eq_px / 2 × Dq           # для идеального режима S = 0
N = max(1, ceil(4 × (L + S)))
tau_k = time_us - exposure_us/2 + (k + 0.5) × exposure_us/N
```

`k` меняется от 0 до `N-1`. На каждом отсчёте заново рассчитываются центр и полуоси по согласованному закону округления. `S` — консервативная оценка изменения границы формы: при `q >= 1` модули производных обеих полуосей по `q` не превышают `diameter_eq_px/4`. Выбор `N` ограничивает перемещение точек контура между временными отсчётами сверху величиной `0,25` пикселя. Предварительно проверяется конечность этих вычислений.

Временные значения `P` и `A` усредняются с весом `1/N`: увеличение выдержки не увеличивает суммарную яркость слоя. Набор капель фиксируется по середине выдержки; отдельные временные отсчёты не создают и не удаляют ID. Для новой капли её траектория продолжается назад от момента появления, включая положения за границей кадра. Предварительное отсечение такого следа по геометрии середины выдержки недопустимо.

### Расфокусировка, шум и запись яркости

Гауссова расфокусировка применяется к усреднённым пиксельным `P` и `A` одинаковым разделимым ядром. Для `sigma > 0` радиус ядра — `ceil(4 × sigma)` пикселей, веса пропорциональны `exp(-k²/(2 × sigma²))` и нормируются до суммы 1. `sigma = 0` означает тождественное преобразование. За пределами отрисованного слоя используются нули. При вычислении кадра учитывается слой вне кадра в пределах радиуса ядра; обрезание до границ изображения выполняется после размытия. Нормировать ядро заново возле края кадра нельзя.

После наложения слоёв для каждого пикселя добавляется независимый нормальный шум с нулевым средним и `background.noise_sigma`. Новая реализация шума создаётся для каждого кадра. Затем применяется ограничение яркости к `[0,1]` и единственное преобразование в целочисленные отсчёты:

```text
encoded = floor(clamp(I, 0, 1) × (2^bit_depth - 1) + 0.5)
```

PNG сохраняется без потерь с уровнем сжатия 6, TIFF — без сжатия. Экспорт одноканальный, без альфа-канала, гамма-преобразования, ID, векторов или других элементов предпросмотра. Изображения не содержат меняющихся временных метаданных.

Проверка длины следа в D09 использует изолированный идеальный круг вдали от краёв, выключенные шум и расфокусировку. Проверяется растровая маска покрытия до целочисленного квантования: протяжённость ненулевого покрытия вдоль движения минус исходный диаметр должна отличаться от `L` не более чем на 1 пиксель. Оценка проводится по проекциям центров покрытых пикселей. Произвольный порог яркости в готовом PNG для этой проверки не используется: при большой выдержке слабый след может исчезнуть после квантования. Точность этой численной схемы должна быть проверена при реализации, а не считаться подтверждённой настоящим документом.

## 4. Контракт CSV и имён файлов

- Папка серии: `series_YYYYMMDD_HHMMSS_<seed>`. При совпадении имени добавляется первый свободный суффикс `_001`, `_002` и далее. Существующие серии не перезаписываются.
- Внутри: `frames`, `droplets.csv`, `config.json`. Кадры: `frame_000001.png` или `frame_000001.tif`, нумерация с 1, всегда шесть цифр.
- CSV: UTF-8 без BOM, разделитель запятая, десятичная точка, конец строки LF, включая последнюю строку. Локаль Windows не меняет формат.
- Целые числа записываются обычными десятичными цифрами; логические значения — строго `true` и `false`.
- Для конечных `float64` применяется формат `.17g`: до 17 значащих цифр, с научной записью при необходимости. Значение `-0` нормализуется в `0`. Значения не округляются заранее до фиксированного числа десятичных знаков.
- Строки идут по возрастанию `frame_number`, затем `droplet_id`. ID начинаются с 1, выдаются последовательно и никогда не используются повторно в серии. Для всех первоначальных капель `is_new=true` на первом кадре.
- CSV содержит только полностью зафиксированные кадры, по `count_per_frame` строк на каждый. Согласованная фиксация изображения, строк и счётчика реализуется в D07.

Порядок 19 столбцов:

```csv
frame_number,time_us,droplet_id,is_new,center_x_px,center_y_px,center_x_mm,center_y_mm,diameter_eq_px,diameter_eq_um,semi_major_px,semi_minor_px,angle_deg,vx_m_s,vy_m_s,speed_m_s,blur_sigma_px,border,overlap
```

Учебный пример для идеальной капли диаметром `100` мкм при масштабе `10` мкм/пиксель, без расфокусировки, с постоянной скоростью `(2,0)` м/с и интервалом `100` мкс:

```csv
1,0,1,true,100,100,1,1,10,100,5,5,0,2,0,2,0,false,false
2,100,1,false,120,100,1.2,1,10,100,5,5,0,2,0,2,0,false,false
```

Это условный пример геометрии, не выборка из стартового JSON с диапазоном скорости `4–12` м/с. В реалистичном режиме постоянный угол эллипса сохраняется в CSV даже при достижении `q=1`; в идеальном режиме угол всегда нулевой. Направление движения не подменяет угол эллипса.

## 5. Метаданные запуска и совместимость

Настройки, сохранённые до генерации, имеют `run: null`. В папке серии `run` содержит следующие обязательные поля:

| Поле внутри `run` | Тип и смысл |
|---|---|
| `status` | `"running"` во время работы; итоговый `"completed"`, `"cancelled"` или `"error"` |
| `started_at` | Строка ISO 8601 с часовым поясом, время начала запуска |
| `completed_frame_count` | Целое число полностью зафиксированных кадров от 0 до `camera.frame_count` |
| `output_directory` | Абсолютный путь фактической папки этой серии |
| `environment` | Объект с описанием окружения из следующей таблицы |

При `completed` число кадров равно запрошенному. При отмене и ошибке сохраняется фактическое число; незавершённый кадр не считается готовым. Статус хранится в `run.status`; отдельного поля `status` в корне конфигурации нет.

| Поле внутри `run.environment` | Тип и смысл |
|---|---|
| `os` | Непустая строка версии и сборки Windows |
| `architecture` | Непустая строка архитектуры процесса |
| `processor` | Непустая строка модели процессора |
| `runtime` | Объект `name`, `version`: название и версия выбранной среды исполнения |
| `dependencies` | Объект соответствий имени зависимости и точной версии, включая численные библиотеки и кодеки |
| `build_id` | Непустой идентификатор конкретной сборки программы |
| `numerical_profile` | `"standard-v1"`, версия численных правил из разделов 2–3 |

Для строковых метаданных недопустимы пустые значения. Выбор стека остаётся работой D02; контракт не утверждает, что приложение уже написано на определённом языке. Результат сохранения всегда записывает фактическую версию программы. При загрузке экспортированной серии её сведения об окружении сохраняются для сравнения до следующего запуска.

Загрузка требует всех обязательных полей и правильных типов. Неизвестные поля совместимой схемы игнорируются с предупреждением. Поддерживается версия `1.0`; более новая минорная версия `1.x` может быть прочитана с предупреждением, только если все известные обязательные поля, их значения и фиксированный профиль совместимы. Другая основная версия схемы, неизвестные значения перечислений или неизвестный профиль — ошибка. Различие версии программы или окружения само по себе не запрещает загрузку совместимой конфигурации, но снимает гарантию точного повтора и вызывает предупреждение.

Загрузка `cancelled` или `error` восстанавливает настройки и seed для новой генерации с первого кадра; возобновления с промежуточного состояния нет. Путь вывода, время, статус и счётчик предыдущего запуска не входят в случайные входные данные.

## 6. Границы повторяемости

Одинаковые настройки генерации и seed должны давать побайтово одинаковые изображения и CSV при одной сборке программы, одинаковых версиях среды, библиотек и кодеков, численном профиле и вычислительном окружении. Практический гарантируемый сценарий — повтор в той же установленной версии приложения на том же компьютере. Совпадение одних только названий версий на разных компьютерах недостаточно для обещания идентичности.

Алгоритм генератора случайных чисел, порядок выборок и способ создания независимых потоков фиксируются в реализации и версии сборки. Выбор конкретной библиотеки выполняется в D02. Случайность модели и сенсорного шума разделяется: включение шума не изменяет геометрию и CSV. Предпросмотр не расходует состояние генерации экспортируемой серии; экспорт начинается заново от сохранённого seed. Параллельное выполнение не должно менять порядок результатов или выборок.

Идентичность `config.json` побайтово не требуется: фактические время, путь, статус и число готовых кадров могут различаться. Все настройки, влияющие на модель и изображение, должны совпадать. Обновление алгоритма, численного профиля, библиотек, кодека или окружения не даёт прежней гарантии; соответствующее предупреждение показывается до повтора.

## 7. Проверяемые примеры и последующая реализация

| Вход или действие | Ожидаемый результат |
|---|---|
| Стартовый JSON с `run=null` и невыбранной папкой | Настройки можно загрузить и просмотреть; перед экспортом требуется выбрать папку |
| `seed=0` или `seed=4294967295` | Допустимо |
| `seed=-1`, `4294967296`, `"1"` или `true` | Ошибка поля seed |
| `exposure_us=101`, интервал `100` | Ошибка до генерации |
| `format="tiff"`, `bit_depth=8` | Ошибка сочетания формата и разрядности |
| `defocus_enabled=false`, границы `0–2` | Границы сохраняются; фактическая сигма каждой капли в CSV равна 0 |
| Идеальный режим с явно загруженной включённой расфокусировкой | Настройка остаётся включённой |
| Два повтора одного seed в одинаковом окружении, между ними предпросмотр | Кадры и CSV побайтово одинаковы |
| Повтор с включённым вместо выключенного шумом | Геометрия и CSV совпадают; изображение может отличаться |
| Изменение сборки или окружения | Загрузка совместимой конфигурации с предупреждением об отсутствии гарантии точного повтора |

Эти примеры задают будущие проверки D02, D05–D09, а не отчёт об их прохождении. Структура стартового JSON и согласованность документации проверяются в D01. Согласование завершено, полный JSON включён в ТЗ, зависимые локальные issues синхронизированы. Сравнение реализованных изображений с референсами остаётся открытой зависимостью D06/D09.
