## Представления и хранение

1. В `Configuration`, JSON и модели остаются существующие физические поля, схема 1.0. Не добавлять Гц, пиксельные диаметры, справочную скорость или настройки UI в JSON. Не менять CSV, RNG, выборку, движение и рендер.
2. При запуске окна единицы интервала — мкс, размеров — мкм. Два независимых readonly-переключателя: мкс/Гц для интервала и один общий мкм/пикс для всех четырёх размеров. Выбор сохраняется в памяти окна при загрузке JSON и сбросе конфигурации; после перезапуска возвращается к мкс/мкм. Постоянных настроек, sidecar и изменений схемы нет.
3. При Гц подпись поля — «Частота кадров (Гц)», при мкс — «Межкадровый интервал (мкс)». Выдержка всегда в мкс. Подписи среднего, стандартного отклонения, медианы и максимального эквивалентного диаметра показывают выбранные единицы. `geometric_std` безразмерен и не преобразуется. Неактивные параметры обоих распределений тоже переключаются и сохраняются.
4. Средняя скорость остаётся вводимой в м/с. Добавить readonly-показатель «Средняя скорость (пикс/кадр)» с пояснением «Пересчёт заданной средней скорости». Это скаляр по заданному среднему исходного распределения, без вычисления статистики капель или компонентов скорости.
5. Рядом с переключателем размеров постоянно видимое пояснение: «Эквивалентный диаметр до размытия. При смене масштаба размеры в мкм сохраняются». Это правило относится также к среднему, медиане и стандартному отклонению.

## Формулы, точность и масштаб

Для положительных конечных `dt_us`, `scale_um_per_px` и частоты:

```text
f_Hz = 1e6 / dt_us                  dt_us = 1e6 / f_Hz
d_px = d_um / scale_um_per_px       d_um = d_px * scale_um_per_px
v_px_frame = speed_mean_m_s * dt_us / scale_um_per_px
```

Последняя формула применима к заданному конечному среднему, включая допустимые текущим контрактом значения вне диапазона выборки при ненулевом разбросе. Новое ограничение положительности среднего не вводить. Коэффициент 1e6 в формуле скорости не нужен: перевод метров в микрометры сокращается с переводом микросекунд в секунды.

Физическое значение — источник истины. Смена единиц только заново форматирует его; нельзя последовательно конвертировать уже округлённый текст туда и обратно. Хранить Python float без дополнительного округления; редактируемые поля форматировать с 17 значащими цифрами (например, `.17g`), справочную скорость — с 6 значащими цифрами. Научная запись допустима; целые примеры могут отображаться без дробной части. Только реальное редактирование текста пользователем меняет физическое значение; неизменённое поле повторно не конвертировать при проверке/сохранении.

Для пересчёта с реальным вводом и roundtrip числовой допуск: `math.isclose(actual, expected, rel_tol=1e-12, abs_tol=1e-12)` в единицах проверяемого значения. Для 1000 переключений без ввода физические поля должны быть точно равны исходным. Для справочного форматирования: `rel_tol=5e-6, abs_tol=5e-6`. Переполнение и обнуление положительного интервала/размера при преобразовании — ошибка, а не округление в 0; ненулевое значение не должно молча исчезать из-за underflow.

При изменении масштаба сохранять физические значения всех четырёх размерных полей, пересчитывая только их показ в пикселях. Перед сменой масштаба обработать пользовательский ввод размера по прежнему масштабу. Если изменение делает конфигурацию недопустимой (например, максимум меньше нового минимума), показать ошибку и оставить черновик для исправления; автоматически увеличивать диаметры или уменьшать масштаб нельзя.

## Состояние ввода, обновления и ошибки

Разделить последний валидный `Configuration`, черновые физические значения и текст полей; конкретные имена и размещение вспомогательных функций выбирает T01. Числовые поля, нужные для преобразований, должны сохранять незавершённый текст (например, через StringVar). Одного перехвата исключений DoubleVar недостаточно.

- Пробелы по краям допустимы, десятичная точка и научная запись поддерживаются. Десятичная запятая не обязательна: при её отсутствии в парсере явно сообщать «Используйте точку как десятичный разделитель». `10000` и `1e4` допустимы; разделители разрядов внутри числа не поддерживаются.
- При каждом изменении корректный числовой текст переводится в черновое физическое значение. Проверить конечность входа и результата, положительность частоты/интервала/масштаба и ограничения соответствующего поля. Все межполевые ограничения проверять через `from_mapping` на полном кандидате. Только полностью валидный кандидат становится `self.config` и обновляет предпросмотр.
- Пустая строка, `-`, `.`, `1e`, `NaN`, `inf`, нулевая/отрицательная частота или масштаб, переполнение остаются видимыми для исправления. Во время набора не показывать модальные окна на каждый символ: дать сообщение в строке состояния, называющее поле, единицы и причину. После исправления снять актуальную ошибку. Не заменять ошибочное поле прежним значением и не пропускать его при сборке конфигурации.
- При невалидном черновике не строить новый предпросмотр; последний валидный можно оставить с явной подписью «Предпросмотр по последним корректным настройкам». Справочную скорость показывать как «—» до полной валидности черновика. При валидности пересчитывать её сразу при изменении среднего, масштаба, интервала/частоты и после загрузки/сброса.
- Переключение единиц требует численно корректных затрагиваемых полей; при незавершённом вводе размера/масштаба или интервала отменить соответствующее переключение, сохранив текст и прежние единицы, и показать причину. Межполевая ошибка при численно корректном черновике не запрещает смену представления. Изменение масштаба при незавершённом размере не применять к физическому черновику до исправления размера; сохранить прежний масштаб преобразования. Это предотвращает интерпретацию старого текста по новому масштабу.
- «Проверить», «Сохранить…» и «Запустить генерацию» обязательно валидируют весь текущий черновик. При ошибке — понятное модальное сообщение и отсутствие записи/запуска. Нельзя молча сохранить или запустить последний валидный `self.config`. Допустимо устранить существующий пропуск ошибок в общем пути чтения полей настолько, насколько нужно для этого требования; не проводить общий рефакторинг UI.
- Загрузка валидного JSON атомарно заменяет конфигурацию и черновик, очищает ошибки, обновляет все представления с сохранением выбранных единиц. Ошибка загрузки сохраняет предыдущее состояние. Во время массовой записи полей подавить trace/callbacks и выполнить одну итоговую синхронизацию. Не вызывать частичные обновления конфигурации на промежуточных сочетаниях старых и новых данных.

Ограничения `from_mapping` остаются прежними: максимум диаметра не меньше 3 пикселей, std неотрицателен, median положительна, geometric_std >= 1; фиксированный диаметр при нулевом разбросе входит в диапазон. Нельзя требовать среднее/медиану >= 3 пикселей при ненулевом разбросе, а также std >= 3 пикселей. `exposure_us <= dt_us` проверяется после перевода частоты; при 20 мкс частота 50 000 Гц допустима, 100 000 Гц недопустима. Выдержку автоматически не корректировать. Диапазоны стрелок Spinbox не становятся новыми ограничениями контракта и должны соответствовать выбранным единицам; ручной допустимый ввод вне прежних UI-диапазонов не обрезать.
