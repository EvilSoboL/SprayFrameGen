## Первоначальные дефекты для T01 (впоследствии исправлены)

**F01, высокий приоритет — устаревшие пиксельные размеры после исправления масштаба.**

1. Новая конфигурация: масштаб 10, медиана 120 мкм, максимум 500 мкм. Выбрать пиксели: медиана 12.
2. Ввести масштаб 200: ожидаемо ошибка, поскольку максимум меньше 600 мкм.
3. В поле максимума ввести 5 пикс. Конфигурация теперь валидна: максимум 1000 мкм, масштаб 200, медиана 120 мкм.
4. Фактически поле медианы всё ещё показывает 12 пикс. Ожидается 0.6 пикс. Аналогично устаревают другие неизменённые размерные поля и границы Spinbox.

Причина: [app.py:324](../../../sprayframegen/ui/app.py#L324) перерисовывает размеры только в успешном callback самого масштаба. Когда ошибку устраняет другое поле, конфигурация получает новый масштаб, а представления не синхронизируются. Это нарушает AC02/AC05 и создаёт расхождение между видимым размером и сохраняемой физической величиной. После успешной валидации нужно согласовать зависимые представления с фактически принятым масштабом, не теряя незавершённые поля.

**F02, высокий приоритет — ошибка открытия JSON стирает черновик.**

1. В поле интервала оставить `1e`; появляется ошибка, справочная скорость равна «—».
2. Открыть отсутствующий, повреждённый или недопустимый JSON.
3. После сообщения об ошибке фактически введённое `1e` заменяется прежним `100`, ошибка черновика снимается, скорость снова 80. Ожидается полное сохранение прежнего состояния окна, включая текст, черновик, сообщение и единицы.

Причина: [app.py:665](../../../sprayframegen/ui/app.py#L665) восстанавливает объекты конфигурации/черновика, затем `_vars_from_config()` записывает последнюю валидную конфигурацию поверх пользовательского текста. Это нарушает атомарность загрузки из контракта и AC04/AC05. Ошибка чтения/валидации должна оставлять окно без изменений; при возможной ошибке отображения также требуется восстановить весь UI, а не только Configuration.
