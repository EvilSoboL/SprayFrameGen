## API и порядок композиции

Сохранить вызываемый API `SettingsWindow._draw_overlay(self, img, frame, camera) -> Image.Image`. `frame` — `Frame` с `FrameDroplet`; `camera` — `Camera` конфигурации, из которой создан кадр. Вход `img` — чистое 8-битное экранное представление кадра, в том числе после преобразования 16-битной яркости. Результат того же размера в `RGB` или `RGBA`, содержащий цветной служебный слой.

Метод не меняет входное изображение, `frame`, `camera`, конфигурацию или RNG. Результат используется только для `ImageTk.PhotoImage`. Пустой `frame.droplets` поддерживается.

Сначала подготовить чистый предпросмотр и его размер для Canvas, затем наложить слой. Это сохраняет читаемые ID и толщину линий при уменьшении. При выключенном переключателе остаётся чистое изображение. Размеры, поля и геометрия чистого предпросмотра сохраняются; его известные расхождения с экспортом — отдельная задача D08.

Пусть `sx=img.width/camera.width_px`, `sy=img.height/camera.height_px`. Геометрию сначала вычислять в координатах исходного кадра, затем применять `sx`, `sy` ко всем точкам. Смещение изображения на Canvas применяется одинаково к кадру и слою. Толщина основных линий — 2 экранных пикселя; текст — читаемый экранный шрифт с контрастной подложкой/обводкой. Конкретный шрифт и размещение вспомогательных функций выбирает T01.

## Контур и граничная отметка

Для центра `(cx, cy)`, `a=state.semi_major_px`, `b=state.semi_minor_px`, `theta=radians(d.angle_deg)`:

```text
X(t) = cx + a*cos(t)*cos(theta) - b*sin(t)*sin(theta)
Y(t) = cy + a*cos(t)*sin(theta) + b*sin(t)*cos(theta)
x(t) = sx*X(t), y(t) = sy*Y(t), 0 <= t <= 2*pi
```

`0°` направляет большую полуось вправо; `90°` — вниз; `45°` — вправо-вниз. Для круга поворот не меняет контур. Полуоси описывают геометрическую проекцию в момент кадра, до оптических эффектов. Не вычислять их повторно из начального диаметра или параметров распределения.

Разрешена замкнутая ломаная с отклонением от аналитического контура не более 0,5 экранного пикселя. Число сегментов подобрать по размеру эллипса; контрольная точка на середине каждого сегмента должна укладываться в этот допуск. При растровой проверке допуск на линию/округление — 1 пиксель сверх половины толщины штриха. Численные проверки точек до растеризации: `rel_tol=1e-12`, `abs_tol=1e-9` пикселя.

Для `state.border=true` рисуется красная прямоугольная рамка вокруг **повёрнутого** эллипса с внешним отступом 2 экранных пикселя:

```text
hx = hypot(a*cos(theta), b*sin(theta))
hy = hypot(a*sin(theta), b*cos(theta))
рамка = (sx*(cx-hx)-2, sy*(cy-hy)-2,
         sx*(cx+hx)+2, sy*(cy+hy)+2)
```

Части контура и рамки за кадром обрезаются. Флаг `state.border` — источник истины; слой его не пересчитывает. ID берётся из `d.droplet_id` и размещается рядом с фактическими границами контура, с переносом внутрь изображения, если подпись иначе выходит за край. При пересечениях капель допустимо наложение подписей; отдельный алгоритм разведения подписей в эту задачу не входит.

## Стрелки: длина, направление, крайние случаи

```text
dx_px = d.vx_m_s * camera.frame_interval_us / camera.scale_um_per_px
dy_px = d.vy_m_s * camera.frame_interval_us / camera.scale_um_per_px
начало = (sx*cx, sy*cy)
конец  = (sx*(cx+dx_px), sy*(cy+dy_px))
```

Это перемещение центра за один интервал при его текущей скорости, включая направление вверх при `vy_m_s<0`. Стрелка не обещает сохранение ID за пределами кадра: модель может заменить вышедшую каплю. Выдержка и `motion_blur_enabled` не меняют эту геометрию.

Стрелку рисовать поддерживаемыми Pillow примитивами: отрезок и треугольный наконечник. Полная длина считается от центра до вершины наконечника. Для экранной длины `L>=1` длина наконечника `min(6, L/3)` пикселя, его половина ширины `min(3, L/6)`; вершина находится в рассчитанном конце, основание направлено назад вдоль вектора. Направление нормализовать только для построения наконечника.

- При строго нулевом векторе не рисовать стрелку; ID и контур сохраняются. Деления на ноль нет.
- При `0<L<1` экранного пикселя показать бирюзовую точку в рассчитанном конце вместо увеличения длины. В легенде объяснить это представление.
- Для длинного вектора сохранять масштаб 1:1 с кадром; обрезать геометрию границами изображения. Если истинный конец снаружи, наконечник не переносить на край. Видимая часть отрезка остаётся; легенда объясняет обрезку.
- Поддержать центр частично видимой капли за краем: клиппинг отрезка выполняется относительно всей рассчитанной геометрии, без принудительного переноса центра внутрь кадра.

## Легенда

Краткая русская легенда рядом с предпросмотром видна при включённом слое. Для небольшого окна использовать перенос строк. Она объясняет реальные обозначения и остаётся читаемой на обоих фонах:

| Обозначение | Цвет RGB | Смысл |
| --- | --- | --- |
| Число и контур | `(255,255,0)` — жёлтый | ID капли и геометрический контур до размытия |
| Стрелка | `(0,255,255)` — бирюзовый | Перемещение центра за один межкадровый интервал, пикс/кадр |
| Рамка | `(255,0,0)` — красный | Граничная капля: часть геометрической проекции снаружи кадра (`border=true`) |

Дополнительная строка: «Нулевая скорость — без стрелки; меньше 1 экранного пикселя — точка; за краем стрелка обрезается. Служебный слой не экспортируется». Можно использовать непрозрачные цвета; при альфа-композиции сохранять различимость и соответствие цветовых образцов легенды.

Общий механизм подсказок уже реализован в ISSUE-002/T01. Его текст про `preview.overlay` пока перечисляет элементы без спорного смысла длины стрелки. Финальную сверку справки выполняет ISSUE-002/T02 после Q01 этой задачи; легенда — часть текущей T01.
